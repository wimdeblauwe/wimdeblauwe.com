This blog post is the first in a series showing how to build a Spring Boot with Thymeleaf application using the https://shadleaf.dev/[Shadleaf component library].
Over the course of 10 parts, we will build Spendleaf, an expense tracker for a small team.
Employees enter expenses and attach receipts, and managers approve or reject them.
The app touches almost every part of Shadleaf: the https://shadleaf.dev/current/components/application-shell/[application shell], https://shadleaf.dev/current/components/table/[tables], https://shadleaf.dev/current/components/field/[forms], https://shadleaf.dev/current/components/dialog/[dialogs] and https://shadleaf.dev/current/components/sheet/[sheets], https://shadleaf.dev/current/components/file-upload/[file uploads], https://shadleaf.dev/current/components/user-menu/[roles] and https://shadleaf.dev/current/components/chart/[charts].

<!--more-->

In this first part, we will set up the project and create the application shell.

    --name Spendleaf \
    --java-version 25 \

<.> Use the https://shadleaf.dev/current/components/theme-toggle/[`sl:theme-toggle`] component to add a button that lets the user switch between light and dark mode.
<.> This line adds a https://shadleaf.dev/current/components/button/[button], just as an example of a component.

== Application shell

The application needs a basic structure with a navigation part and a main content part.

Shadleaf has many https://shadleaf.dev/current/layouts/[example layouts] you can choose from.
We will use https://shadleaf.dev/current/layouts/collapses-to-icons/[collapses-to-icons] here.

It uses this structure:

[source]
----
  <body>
   └─ sl:skip-link
   └─ sl:sidebar-provider          ← wraps everything, holds expanded/collapsed state
       ├─ sl:sidebar               ← the <nav>: header, content (menus), footer
       └─ sl:sidebar-inset         ← the page's <main id="main">
           ├─ sl:site-header       ← row with trigger, separator, breadcrumb, theme toggle
           │    └─ sl:sidebar-trigger
           └─ your page content
----

This is what each part does:

* `<sl:sidebar-provider>` wraps the whole page and keeps track of whether the sidebar is expanded or collapsed on a desktop.
The current setting is automatically stored in a cookie.
Keyboard users can use Ctrl/⌘+B to toggle it.
* `<sl:sidebar>` is the navigation itself, rendered as a `<nav>` landmark.
It has three parts: `sidebar-header` (logo or app name),
`sidebar-content` (groups and menus) and `sidebar-footer` (the user menu).
It must be a direct child of the provider, because the CSS that collapses it looks for it there.
Two props are important for Spendleaf:
** `variant="inset"` shows the page as a card next to the sidebar.
** `collapsible="icon"` collapses the sidebar to a strip of icons with tooltips.
The alternative, `collapsible="offcanvas"`, slides it out of view instead.
* `<sl:sidebar-inset>` renders the page's single `<main id="main" tabindex="-1">`.
That is also the target of the skip link, so all page content goes inside it.
* `<sl:site-header>` is a header that lays out its children in a row.
It has an end slot for things that belong on the right, like the theme toggle.
Inside the inset, it holds the `<sl:sidebar-trigger>` (the button that collapses the sidebar on a desktop and opens it as a panel on a phone), a vertical separator and the breadcrumb.

Below 768 px, the same `<sl:sidebar>` element opens as a panel over the page, so you don't need separate mobile markup.

The https://shadleaf.dev/current/components/skip-link/[`sl:skip-link`] is a component that stays hidden until focused.
It allows a keyboard user to jump directly to the main content without having to go through all the navigation items each time.

Using this structure, we now have this `layout/main.html`:

[source,html]
.src/main/resources/templates/layout/main.html
----
<!DOCTYPE html>
<html lang="en" xmlns:th="http://www.thymeleaf.org" xmlns:sl="https://shadleaf.dev/sl"
      th:fragment="layout(pageTitle, breadcrumb, content)">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title th:text="|${pageTitle} - Spendleaf|">Spendleaf</title>
    <th:block th:replace="~{sl/layout :: theme-script}"></th:block>
    <th:block th:replace="~{sl/layout :: assets}"></th:block>
    <vite:client></vite:client>
    <vite:vite>
        <vite:entry value="/css/application.css"></vite:entry>
    </vite:vite>
    <script defer th:src="@{/webjars/htmx.org/dist/htmx.min.js}"></script>
</head>
<body>
<sl:skip-link/>
<sl:sidebar-provider>
    <sl:sidebar variant="inset" collapsible="icon">
        <sl:sidebar-header>
            <!-- application name -->
        </sl:sidebar-header>
        <sl:sidebar-content>
            <!-- menu items -->
        </sl:sidebar-content>
    </sl:sidebar>
    <sl:sidebar-inset>
        <sl:site-header>
            <sl:sidebar-trigger/>
            <sl:separator orientation="vertical"/>
            <sl:breadcrumb>
                <sl:breadcrumb-list>
                    <th:block th:replace="${breadcrumb}"></th:block>
                </sl:breadcrumb-list>
            </sl:breadcrumb>
            <sl:slot name="end">
                <sl:theme-toggle/>
            </sl:slot>
        </sl:site-header>
        <div class="px-4 pb-4">
            <h1 class="mb-4 text-2xl font-semibold" th:text="${pageTitle}"></h1>
            <div th:replace="${content}"></div>
        </div>
    </sl:sidebar-inset>
</sl:sidebar-provider>
</body>
</html>
----

Note how we don't need to style any of the Shadleaf components.
We do have a little bit of Tailwind CSS styling for the `<h1>` and some padding around the content.

Update `index.html` to use the new layout:

[source,html]
.src/main/resources/templates/index.html
----
<html xmlns:th="http://www.thymeleaf.org" xmlns:sl="https://shadleaf.dev/sl"
th:replace="~{layout/main :: layout('Dashboard', ~{::breadcrumb}, ~{::#page-content})}">
<body>
<th:block th:ref="breadcrumb">
    <sl:breadcrumb-item>
        <sl:breadcrumb-page>Dashboard</sl:breadcrumb-page>
    </sl:breadcrumb-item>
</th:block>
<div id="page-content">
    Dashboard content
</div>
</body>
</html>
----

The index injects 2 parts of html into the layout.
The breadcrumb uses `th:ref` so we can refer to that html snippet using `~{::breadcrumb}`.
Using `th:ref` avoids that the resulting html that Thymeleaf renders has any indication of the reference.
For the page content, we add an `id` of `page-content`, so we can use `~{::#page-content})` to refer to it.

== Navigation

We can now fill in the navigation part on the left.

=== Application name

We will start with the application name and icon.
Inside the `<sl:sidebar-header>`, we put the following snippet:

[source,html]
----
<sl:sidebar-menu>
    <sl:sidebar-menu-item>
        <sl:sidebar-menu-button th:href="@{/}" size="lg" tooltip="Spendleaf">
            <sl:slot name="icon-start">
                <span class="grid size-8 shrink-0 place-items-center rounded-md bg-primary text-primary-foreground">
                    <sl:icon name="leaf" size="16"/>
                </span>
            </sl:slot>
            <strong>Spendleaf</strong>
            <small>Expense tracker</small>
        </sl:sidebar-menu-button>
    </sl:sidebar-menu-item>
</sl:sidebar-menu>
----

The `sl:sidebar-menu-button` is a link, so we give it a `th:href` link, typically to the root of the application.

With `size="lg"`, we can add two lines of text which we use for the application name (`Spendleaf`) and the tagline (`Expense tracker`).

An important concept in Shadleaf is the use of slots.
Many Shadleaf components have slots: named places where you put your own markup. `<sl:slot name="icon-start">` puts its content in the `icon-start` slot of the menu button.
Anything outside a named slot, here the two lines of text, becomes the main content.
You already saw this in the layout, where `<sl:slot name="end">` puts the theme toggle at the right of the site header.

In this example, we put an icon into the `icon-start` slot so it is shown before the application name.
Switch to the `icon-end` slot if you want the icon to the right of the application name.

Shadleaf has an https://shadleaf.dev/current/components/icon/[`sl:icon`] component that contains all https://lucide.dev/[Lucide] icons.
We use it here as the application icon.
To make it look more like a logo, we surround it with a small colored square:

[source,html]
----
<span class="grid size-8 shrink-0 place-items-center rounded-md bg-primary text-primary-foreground">
    <sl:icon name="leaf" size="16"/>
</span>
----

Note how we use `bg-primary` and `text-primary-foreground` which uses Shadleaf's tokens.
Because of that, the square is black in light mode and white in dark mode (with the default theme).

image::2026/11/shadleaf-part-01-03-logo-light.webp[link=/images/2026/11/shadleaf-part-01-03-logo-light.webp]

=== Menu items

The next step is adding the menu items for navigation.

Menu items follow this structure:

[source]
----
  sl:sidebar-content
   └─ sl:sidebar-group (id="…")        ← a named section, e.g. "Expenses"
       ├─ sl:sidebar-group-label       ← heading; screen readers announce "Expenses, group"
       └─ sl:sidebar-group-content
           └─ sl:sidebar-menu          ← a <ul>
               └─ sl:sidebar-menu-item ← an <li>
                   └─ sl:sidebar-menu-button  ← the link: icon slot + label
----

We can apply this in our example by adding this HTML inside the `<sl:sidebar-content>` element:

[source,html]
----
<sl:sidebar-group id="nav-main">
    <sl:sidebar-group-label>Expenses</sl:sidebar-group-label>
    <sl:sidebar-group-content>
        <sl:sidebar-menu>
            <sl:sidebar-menu-item>
                <sl:sidebar-menu-button th:href="@{/}" th:active="${#slNav.current('/')}" tooltip="Dashboard">
                    <sl:slot name="icon-start">
                        <sl:icon name="layout-dashboard"/>
                    </sl:slot>
                    Dashboard
                </sl:sidebar-menu-button>
            </sl:sidebar-menu-item>
            <sl:sidebar-menu-item>
                <sl:sidebar-menu-button th:href="@{/expenses}" th:active="${#slNav.current('/expenses')}"
                                        tooltip="My expenses">
                    <sl:slot name="icon-start">
                        <sl:icon name="receipt"/>
                    </sl:slot>
                    My expenses
                </sl:sidebar-menu-button>
            </sl:sidebar-menu-item>
        </sl:sidebar-menu>
    </sl:sidebar-group-content>
</sl:sidebar-group>
<sl:sidebar-group id="nav-manage">
    <sl:sidebar-group-label>Manage</sl:sidebar-group-label>
    <sl:sidebar-group-content>
        <sl:sidebar-menu>
            <sl:sidebar-menu-item>
                <sl:sidebar-menu-button th:href="@{/approvals}" th:active="${#slNav.current('/approvals')}"
                                        tooltip="Approvals">
                    <sl:slot name="icon-start">
                        <sl:icon name="circle-check"/>
                    </sl:slot>
                    Approvals
                </sl:sidebar-menu-button>
            </sl:sidebar-menu-item>
        </sl:sidebar-menu>
    </sl:sidebar-group-content>
</sl:sidebar-group>
----

This gives the following result:

image::2026/11/shadleaf-part-01-05-menu-items.webp[link=/images/2026/11/shadleaf-part-01-05-menu-items.webp]

Some important things here:

* `<sl:sidebar-group id="nav-main">`: Each sidebar-group optionally takes `id`.
The group uses its id to link its label for screen readers (`aria-labelledby="nav-main-label"`).
Without an `id`, Shadleaf generates a random one on every render, so the HTML changes on each request.
A fixed `id` keeps the output stable for tests and gives you a handle for CSS.
* Each `sl:sidebar-menu-button` has three attributes:
** `th:href="@{/approvals}"` points to the URL that should be navigated to.
** `th:active="${#slNav.current('/approvals')}"` will ensure the menu item is highlighted if the current URL is `/approvals` or a sub-path like `/approvals/12`. `/` is the exception as otherwise Dashboard would be highlighted on every page.
** `tooltip="Approvals"`.
The tooltip is useful when the sidebar is collapsed.
* We again use an `sl:slot` to add an icon at the start of the menu item.

.Collapsed sidebar showing the tooltip
image::2026/11/shadleaf-part-01-06-tooltip.webp[link=/images/2026/11/shadleaf-part-01-06-tooltip.webp]

=== Breadcrumbs

https://en.wikipedia.org/wiki/Breadcrumb_navigation[Breadcrumb navigation] is a widely used pattern to indicate hierarchy and allow the user to easily navigate back to a page higher up in the hierarchy.

In Shadleaf, each page is responsible for adding the breadcrumb trail correctly.
To show how this works, we will add placeholder pages for Expenses and Approvals.
Start by adding two controllers:

[source,java]
.src/main/java/com/wimdeblauwe/examples/spendleaf/expense/web/ExpenseController.java
----
package com.wimdeblauwe.examples.spendleaf.expense.web;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;

@Controller
@RequestMapping("/expenses")
class ExpenseController {
    @GetMapping
    public String index() {
        return "expenses/index";
    }
}
----

[source,java]
.src/main/java/com/wimdeblauwe/examples/spendleaf/approval/web/ApprovalController.java
----
package com.wimdeblauwe.examples.spendleaf.approval.web;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;

@Controller
@RequestMapping("/approvals")
class ApprovalController {
    @GetMapping
    public String index() {
        return "approvals/index";
    }
}
----

For each controller, we write the corresponding HTML template:

[source,html]
.src/main/resources/templates/expenses/index.html
----
<html xmlns:th="http://www.thymeleaf.org" xmlns:sl="https://shadleaf.dev/sl"
      th:replace="~{layout/main :: layout('My expenses', ~{::breadcrumb}, ~{::#page-content})}">
<body>
<th:block th:ref="breadcrumb">
    <sl:breadcrumb-item> <!--.-->
        <sl:breadcrumb-link th:href="@{/}">Dashboard</sl:breadcrumb-link> <!--.-->
    </sl:breadcrumb-item>
    <sl:breadcrumb-separator/> <!--.-->
    <sl:breadcrumb-item>
        <sl:breadcrumb-page>My expenses</sl:breadcrumb-page> <!--.-->
    </sl:breadcrumb-item>
</th:block>
<div id="page-content">
    Expenses content
</div>
</body>
</html>
----

<.> Use `sl:breadcrumb-item` for each item in the breadcrumb.
<.> If an item should be a link that the user can click on to navigate, use `sl:breadcrumb-link` with a `th:href` attribute for the URL.
<.> Use a `sl:breadcrumb-separator` between items.
<.> For the final leaf of the breadcrumb, use `sl:breadcrumb-page`.

Similar for approvals:

[source,html]
.src/main/resources/templates/approvals/index.html
----
<html xmlns:th="http://www.thymeleaf.org" xmlns:sl="https://shadleaf.dev/sl"
      th:replace="~{layout/main :: layout('Approvals', ~{::breadcrumb}, ~{::#page-content})}">
<body>
<th:block th:ref="breadcrumb">
    <sl:breadcrumb-item>
        <sl:breadcrumb-link th:href="@{/}">Dashboard</sl:breadcrumb-link>
    </sl:breadcrumb-item>
    <sl:breadcrumb-separator/>
    <sl:breadcrumb-item>

== Shadleaf code completion

If you are using IntelliJ IDEA for editing, you will have noticed that there is no code completion for the Shadleaf components.

.IntelliJ IDEA showing all Shadleaf tags as unknown
image::2026/11/shadleaf-part-01-08-intellij.webp[link=/images/2026/11/shadleaf-part-01-08-intellij.webp]

IntelliJ IDEA supports https://plugins.jetbrains.com/docs/intellij/polysymbols-web-types.html[Web Types] which allows you to place a JSON file in the project with all the tags and the properties of the tags.
The IDE will use that information to provide code assistance.

There are two ways to get this file for Shadleaf.
If you open the https://shadleaf.dev/current/ide-completion/[IDE Completion] page in the documentation, you can download the file there and copy it into the root of the project.

Alternatively, you can add the following property to `application-local.properties`:

[source,properties]
----
shadleaf.dev.web-types-file=shadleaf.web-types.json
----

When you restart the application, the file `shadleaf.web-types.json` is written to the root of the project.
It is only rewritten when something changed.

[NOTE]
====
Adding the property has an advantage over downloading the file.
If you add your own custom components to your application, their properties will also be added to the generated web-types JSON.
====

After that, all you need to do is inform IntelliJ IDEA of the file through the `package.json`:

[source,json]
.package.json
----
{
  "devDependencies" : {
    "@tailwindcss/vite" : "^4.3.4",
    "@wim.deblauwe/vite-plugin-spring-boot" : "^1.1.1",
    "tailwindcss" : "^4.3.4",
    "vite" : "^8.3.5"
  },
  "name" : "spendleaf",
  "private" : true,
  "web-types": "./shadleaf.web-types.json",
  "scripts" : {
    "dev" : "vite",
    "dev-open" : "vite --open http://localhost:8080",
    "build" : "vite build"
  },
  "type" : "module"
}
----

Now IntelliJ IDEA recognizes the Shadleaf components and provides help and code completion for them.

== Checked prop values

Shadleaf checks if the value passed to a prop is correct.

Suppose you change:

[source,html]
----
<sl:sidebar-menu-button th:href="@{/}" size="lg" tooltip="Spendleaf">
----

to:

[source,html]
----
<sl:sidebar-menu-button th:href="@{/}" size="xl" tooltip="Spendleaf">
----

When the page reloads, Thymeleaf renders the template again, but it will fail with the following exception:

[source]
----
io.github.wimdeblauwe.shadleaf.component.ShadleafComponentException:
Invalid value 'xl' for prop 'size' of <sl:sidebar-menu-button>.
Must be one of: default, sm, lg.
(template: "layout/main" - line 24, col 21)
----

Note how it lists the accepted values, so you quickly know what you can use instead of the wrong value.
Of course, if you use the web-types with IntelliJ IDEA, the value would already be red in the editor as well.

[WARNING]
====
Shadleaf can only validate the values of props, not their names.

If you write `sze="lg"` instead of `size="lg"`, then Shadleaf will not complain. It treats `sze` as a pass-through attribute, so the size is not applied.
This is because any attribute that is not a prop is passed through to the rendered HTML element.
That is needed to support htmx and Alpine.js attributes (`hx-post`, `x-on:click`), `aria-*` and `data-*` for example.
The component cannot know if you mistyped the name of a prop, or if you want that pass-through attribute because some other JavaScript library needs it.
====
